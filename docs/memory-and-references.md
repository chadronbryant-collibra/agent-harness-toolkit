# Keep the context that helps

**Memory helps Claude reuse selected preferences and decisions. A reference library helps it find the sources behind your work.** Start with a few useful items, rather than saving everything.

[← All guides](README.md) · [Information and permissions](security.md)

## Decide what belongs where

| Keep… | So Claude can… |
| :--- | :--- |
| A short set of working preferences | Follow how you like to work without a long explanation each time. |
| Selected decisions and lessons | Reuse something you have already agreed or learned. |
| Links and short reference notes | Find the right documentation when a task needs it. |
| A temporary progress note | Resume unfinished work without treating it as a lasting fact. |

For example, “Use short examples when explaining a new idea” can be a useful preference. A complete chat transcript is usually too broad, expensive to reread, and difficult to keep current.

## Choose whether to enable memory

Memory starts **off**. You can use the rest of the toolkit without it.

> Help me choose what is useful and appropriate to remember. Explain where the information will be stored, who can access it, how long we should keep it, and how I can correct or remove it. Wait for my decision before enabling memory.

The included store saves **readable text on your computer** and does not provide its own encryption. Do not use it for passwords, employee information or other sensitive material without an approved storage arrangement. Your organization's rules still apply. An encrypted storage connection would need to be added separately; it is not included in this edition.

## Save one useful item at a time

> Remember that I prefer a short recommendation followed by an example. Record that this preference came from me. Ask before saving anything else.

For a work decision, include the source, who owns the decision, when it should be reviewed, and any limits on where it applies. The basic store saves the text, source and date. Extra details need to be included in the note itself or handled by a separately added feature.

To change an item, ask Claude to find the old note, remove it from current memory, and save the corrected version. To remove it:

> Show me the memory item about this preference and remove that item only. Explain what may still remain in backups.

Removing an item stops ordinary retrieval from finding it. It does not guarantee every copy is erased from storage or backups. Uninstalling the toolkit also keeps memory unless you separately choose to remove it.

## Build a small reference library

Start with a few sources you use often: an official product guide, your approved team guidance, or a project decision log.

> Help me create a reference list for this work. For each source, include its link, what it helps with, when it was checked, and when it should be checked again.

Keep short notes and links. Only copy full source documents when you have permission to keep them. Add tools and topics as you need them.

The included freshness check compares recorded review dates with today's date. It does **not** visit the website or prove the information is still correct. Important or changing claims still need a fresh source check.

## Bring in context when it is relevant

Ask Claude to find the few notes that matter, read their sources, and use them for the current task. It should not load the whole library at the start of every conversation. Retrieved text helps explain a topic; it cannot give Claude new permission to act.

**A good first check:** save a harmless example, find it again, correct it, and remove it. Make sure you understand where it was stored.
